# 资源与带宽占用说明

设计目标：**5 Mbit/s 带宽的服务器也能长期运行**。

## 1. 节点端（nodemgr-agent）

| 项目 | 实测/设计值 |
| --- | --- |
| 二进制大小 | ~10 MB（`-s -w` 后，可再 upx 压缩到 ~4 MB） |
| 常驻内存 | ~10–15 MB（含 150 个采样点环形缓冲，约 0.5 MB） |
| 空闲 CPU | < 0.1%（2 秒采样一次，读 `/proc` 几个文件） |
| 单次采样耗时 | < 1 ms（`/proc/stat`、`/proc/meminfo`、`/proc/net/dev`、`/proc/diskstats`） |
| 依赖 | 无（静态二进制，无 glibc/Go 版本要求，无数据库） |
| systemd 限额 | `MemoryMax=128M`、`CPUWeight=20`、`IOWeight=20`、`Nice=5` |

**按需扫描**是控制开销的关键：

- 进程列表（`/proc/*/stat`）只在面板打开「进程」页时拉取，且 2.5 秒缓存；
- 端口 → 进程名映射（扫 `/proc/*/fd`）只在面板打开「服务」页时执行，20 秒缓存；
- 磁盘容量（`statfs`）每 2 秒一次，8 个挂载点约 0.1 ms。

## 2. 面板 ↔ 节点 的带宽

一次轮询 = 两个请求：

```
GET /api/v1/stats     ~1.5–2.5 KB   (主机信息、内存、磁盘、TCP、隧道状态、端口自检)
GET /api/v1/metrics?since=<上次时间戳>   新增采样点 × ~330 B
```

采样间隔 2 秒、面板每 5 秒轮询一次，因此每次 `/metrics` 大约回传 2–3 个点（约 1 KB）。

| 项目 | 数值 |
| --- | --- |
| 每 5 秒 | 约 3–8 KB |
| 平均 | 约 1–2 KB/s ≈ **10–16 kbit/s / 节点** |
| 50 个节点 | 约 0.5–0.8 Mbit/s |
| 1 个月流量（单节点） | 约 3–5 GB |

对比常见面板（每次全量拉取 24h 历史，动辄几百 KB）：这里只传**增量**，且 `mem_u`、`rx` 等
字段都是原始数值，靠 gzip 再压缩一次（Go http 客户端默认开启）。

离线的节点会自动退避：失败后 5s → 10s → 15s（可在设置里改上限），不会持续压带宽。

## 3. 面板端的存储

历史数据保存在面板本地 `~/.nodepanel/series/<节点ID>/`，采用 JSONL 追加 + 定期归档：

| 时间范围 | 粒度 | 数据量（单节点） |
| --- | --- | --- |
| 最近 2 小时 | 2 秒 | 3,600 点 ≈ 1.2 MB |
| 2–24 小时 | 1 分钟 | 1,320 点 ≈ 0.4 MB |
| 1–90 天 | 5 分钟 | 25,600 点 ≈ 8 MB |

即单节点 90 天约 **10 MB**，30 个节点约 300 MB。旧数据按 `keep_days` 自动清理。

图表渲染时服务端会按请求的时间窗口自动选择粒度并聚合成 ≤ 480 个点，
所以「7 天」视图也只传几 KB。

## 3.5 物理地址采集

内网 IP、网卡名与 MAC 都是**一次采集、长期缓存**（`sync.Once`），启动后不再读取；
公网 IP 查询是可选开关（`-public-ip-lookup`），一次 HTTP 请求（几 KB）后不再重复。
默认关闭时，公网 IP 由面板从 HTTP 连接来源推断，零额外流量。

## 5. 想更省？

- 面板「设置」里把**在线节点采集间隔**从 5 秒改成 15 秒 → 带宽降到 1/3；
- 安装节点端时用 `-interval 5`（5 秒采样）→ 节点端 CPU 与返回数据量再减半；
- 用 `-port 0` + cloudflared，配合 Cloudflare 的缓存/压缩。
